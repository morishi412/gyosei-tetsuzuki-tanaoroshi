# 行政手続等の棚卸調査ダッシュボード（非公式）

デジタル庁「行政手続等の棚卸調査結果（令和7年度）」を検索・集計するための HTML ダッシュボードです。
配色・タイポグラフィは元資料を参照していますが、**個人が作成した非公式のビューア**であり、
デジタル庁・日本政府とは一切関係ありません（画面上部・下部にその旨を明示）。

## 使い方

1. `start-server.bat` をダブルクリック（Python が必要です）
2. ブラウザで **http://localhost:8000/** を開く

> `docs/index.html` を直接ダブルクリック（`file://`）しても動きません。
> ブラウザが WebAssembly とデータベースファイルを読み込めないためです。必ずローカルサーバ経由で開いてください。

Claude Code から動かす場合は `.claude/launch.json` の `dashboard` 構成、または:

```bash
py -m http.server 8000 --directory docs
```

## GitHub Pages で公開する

動きます（静的ファイルのみ・外部通信なし・すべて相対パス）。

- **配信元**：サイトの実体は `docs/` フォルダです。リポジトリ設定 → Pages →
  「Deploy from a branch」→ Branch: `main` / `/docs` を選択（GitHub Actions のワークフローは不要）。
- **`.nojekyll`**：`docs/.nojekyll` を同梱済み（`.wasm` / `.gz` や `vendor/` をそのまま配信させるため）。
- **公開範囲**：Private リポジトリでも、無料プランの GitHub Pages はサイトが**公開**されます
  （URL を知っていれば誰でも閲覧可）。Private ページ化は GitHub Enterprise 限定。
- **DB ファイル**：`docs/procedures.db.gz` は約8MB。GitHub の 100MB/ファイル制限内です。
  ブラウザ側で `DecompressionStream` により解凍します（Chrome/Edge、Firefox 113+、Safari 16.4+）。
  ホストが転送時に自動解凍した場合も検知してそのまま読み込みます。
- 初回のみ約8.7MB（DB + WASM + ライブラリ）をダウンロードし、以降はブラウザキャッシュから読み込みます。

## 構成

| ファイル | 内容 |
|---|---|
| `20260826_..._02.xlsx` | 元データ（本体）。1行=1手続、46項目、76,275件 |
| `20260826_..._01.pdf` | 調査結果概要（グラフ・分析） |
| `20260826_..._03.pdf` | 解説資料（各項目の定義） |
| `build_db.py` | xlsx → SQLite 変換スクリプト |
| `docs/procedures.db.gz` | sql.js 用 SQLite DB（gzip 圧縮、約8MB） |
| `docs/columns.json` | 列コードとラベルの対応表 |
| `docs/vendor/sql-wasm.*` | [sql.js](https://sql.js.org) v1.13.0（SQLite/WASM） |
| `docs/index.html` / `styles.css` / `app.js` | ダッシュボード本体 |

## 仕組み

- `build_db.py` が Excel を読み、SQLite の `procedures` テーブル（列 `q0`〜`q25`、
  数値列 `total_count` / `online_count` / `offline_count`、検索用 `search_text`）を生成し gzip 圧縮します。
- ブラウザ側では `app.js` が `procedures.db.gz` を取得 → `DecompressionStream` で解凍 →
  **sql.js** でメモリ上の SQLite として開き、すべての集計・検索を SQL クエリで実行します。
- 外部ネットワーク接続なしで動作します（すべてローカルファイル）。

## データを差し替えるとき

新しい Excel を同じ形式で置き、ファイル名を `build_db.py` の `SRC` に合わせて:

```bash
py build_db.py
```

`docs/procedures.db.gz` と `docs/columns.json` が再生成されます。

## 機能

**調査結果の概要タブ**
- 全体サマリー（手続種類数・オンライン化率など）
- オンライン化実施状況の内訳（ドーナツ）
- オンライン化されていない要因
- 所管府省庁別／手続類型別／年間手続件数規模別のオンライン化率
- オンライン化率の推移（参考値）

**ドリルダウン**
- 概要タブの KPI カード・ドーナツ・各グラフの項目をクリックすると、その条件で検索タブへ絞り込み
- 絞り込み条件はチップ表示。個別に「×」で解除、または「すべて解除」
- 詳細パネルから「同じ法令」「所管府省庁×手続類型」「ライフイベント」「情報システム」で関連手続へ再ドリルダウン

**手続を検索タブ**
- キーワード（手続名・法令名・手続ID、スペース区切りAND）
- 所管府省庁・手続類型・オンライン化状況・手続主体・受け手・手数料有無・府省共通・
  ライフイベント（個人／法人）・関連士業での絞り込み
- **手続主体／受け手**は複合選択肢（例「4-4 国、独立行政法人等又は地方等」）を含むため、
  「国 を含む」「地方等 を含む」等を選ぶと該当する複合回答値をまとめて検索（OR）。
  従来どおり回答値そのままの完全一致も選択可能
- 列見出しクリックで並び替え、1画面 最大1,000件表示・ページ送り（表の上下に配置）
- **表示列の切り替え**：
  - 手続ID・手続名・所管府省庁は常に左端に固定表示
  - 手続名の列は 1行目=手続名／2行目=法令名／3行目=「手続主体 → 受け手」を同じ文字サイズで固定表示
  - 「表示列を設定」ボタンで別画面（モーダル）を開き、残り43項目から表示する列を選択（ブラウザに記憶）
  - 選んだ列は ◀▶ ボタンで左右にスクロール表示（表示幅に応じて2〜3列ずつ。タブレットのタッチ操作対応）
- **セルの割合ツールチップ（実験）**：一覧のセルにカーソルを合わせると、その値が現在の検索結果全体の
  何％を占めるかをツールチップ表示（例：手続類型「1 申請等」→ 37,182件中 37,182件 100.0%）。
  結果ヘッダーのチェックボックスでON/OFF（ブラウザに記憶）。列ごとに集計をキャッシュ。
  ホバー前提の機能のため、チェックボックスはマウス操作可能なPC（`hover:hover`）でのみ表示
- 行クリックで全46項目の詳細表示
- 検索結果の CSV 出力

※画面の集計値は読み込んだデータからの再計算であり、端数処理等により公表値（PDF）と完全には一致しない場合があります。
